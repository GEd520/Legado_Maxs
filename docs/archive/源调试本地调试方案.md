# 源调试「本地调试」模式方案

> **适用范围**：书源调试（BookSourceDebugActivity）与订阅源调试（RssSourceDebugActivity）的新增调试模式。
> **状态**：方案已评审、待实现（2026-10-07）。实现落地后本文件按 CLAUDE.md 收尾规则 `git mv` 至 `docs/archive/`。

## 1. 背景与目标

现状：源调试的每个阶段（书源：搜索/发现/详情/目录/正文；订阅源：列表/分类/正文）都要先联网抓取网页，再跑规则解析，阶段间自动串联。每次调试必联网，速度慢；有时只想验证规则本身（尤其 JS 规则的计算逻辑），并不想等网络。

目标：在两个调试界面的溢出菜单增加「本地调试」开关（默认关闭）。开启后调试变成**规则/JS 直跑执行器**：立刻执行源里的规则，全程不发流水线网络请求；只有规则自己要求取网页内容时（如 JS 里的 `java.ajax()`）才发请求，取回的内容接着跑对应的解析规则。

## 2. 行为定义

普通调试（开关关）保持现状不变。本地调试（开关开）下，每个阶段的执行方式：

1. URL 规则照常**在本地立即执行**——`@js:`、`<js></js>`、`{{key}}`/`{{page}}` 替换、URL 选项（method/headers/body 等）解析照常进行，**跳过"取网页内容"这一步**。
2. 规则计算结果二选一：
   - **结果是内容**（如 JS 里 `java.ajax()` 取回的 JSON/HTML）→ 直接作为本阶段网页内容，跑解析规则（搜索列表/详情/目录/正文），链路继续。规则内部发起的取内容请求**照常联网**——这正是"规则写了要获取网页内容，那再跑相应的规则"。
   - **结果是网址** → 把算出的完整请求（URL、method、headers、body）打进调试日志，**不联网**，本阶段到此结束（日志提示"本地调试未取网页内容，调试结束"）。

示例：

- JS 源：`searchUrl = <js>java.ajax("https://api.x.com/list?key=" + key)</js>` → 点调试立即执行 JS（`java.ajax` 照发）→ 返回 JSON 直接跑搜索解析规则出书单 → 进入详情阶段后规则算出的是网址 → 日志打印该请求后结束。
- 普通 URL 源：`searchUrl = https://x.com/search?q={{key}}` → 立即算出并打印请求 → 结束。全程零联网（可开飞行模式验证）。

开关语义：

- 不持久化：每次进入调试界面默认关闭，避免忘记开启导致看到"只有请求没有结果"的日志而困惑。
- 切换在**下次开始调试**时生效，调试中途切换不影响正在跑的会话。

## 3. 技术方案

### 3.1 分支点：AnalyzeUrl

URL 规则在 `AnalyzeUrl` 构造时即本地执行完毕（`initUrl()`：`analyzeJs` → `replaceKeyPageJs` → `analyzeUrl`，结果存于 `ruleUrl`），与网络完全解耦；目前 `getStrResponseAwait()` 不论结果是不是 URL 都会照常发请求。

改造（`app/src/main/java/io/legado/app/model/analyzeRule/AnalyzeUrl.kt`）：

- 新增可置位属性 `var localDebug = false`（默认 false，不影响任何现有调用方）。
- `getStrResponseAwait()`（AnalyzeUrl.kt:420）在 data: URL 短路（`getDataUrlHexContent()`，本身离线，保持最先）之后进入本地调试分支：
  - **内容结果** → 构造 `StrResponse(源地址, 内容)` 返回。后续 loginCheckJs、checkRedirect、`BookList`/`BookInfo`/`BookChapterList`/`BookContent` 解析流程全部原样复用；`res.url` 用源地址充当 baseUrl，保证规则内相对地址解析有合理基准。
  - **网址结果** → 经 `Debug.log` 打印算出的请求摘要（method、URL、headers、body；复用现有 `sanitizeDebugMessage` 折叠 base64 data:），随后抛 `NoStackTraceException`（现有惯例，如"搜索url不能为空"）终止链路，由 `Debug` 的 onError 路径输出日志。
  - 二进制（`type != null`）请求同样按"网址"处理被跳过——调试链路不涉及图片下载。

### 3.2 结果判定规则（纯函数）

判定抽成 companion 纯函数，便于单测：

1. 按 `analyzeUrl()` 同样的 `paramPattern` 切掉尾部 `,{...}` 选项段（选项段只对真实请求有意义，内容分支忽略）。
2. 剩余部分 trim 后：
   - 空 → 视为空结果，提示后结束。
   - 以 `http://`、`https://`（忽略大小写）、`data:`、`/` 开头 → **请求**。
   - 其余（以 `<`、`{`、`[` 开头、含换行/空白等）→ **内容**。

该判定是启发式，极端写法可能误判（见 §5 边界）。

### 3.3 会话标志与传参链

- `Debug` 单例（`model/Debug.kt`）已有 `debugSource` 单活动会话概念，新增 `localDebugSession: String?`（存源 key）：
  - `startDebug` 三个重载（书源 :396、RSS 带 key :287、RSS 无 key :250）增加 `localDebug: Boolean = false` 参数，进入会话时按值设置/清空。
  - `cancelDebug(destroy = true)` 一并清理。
- 传参链：菜单开关 → Activity 字段 → `BookSourceDebugModel`/`RssSourceDebugModel` 的 `startDebug(key, …, localDebug)` → `Debug.startDebug`。
- 置位点：`WebBook` 的 searchBook/explore/getBookInfo/getChapterList（含 Flow 变体）/getContent 与 `Rss` 的 getArticles/getContent 共约 7 处，构造 `AnalyzeUrl` 后按 `Debug` 会话标志置位 `analyzeUrl.localDebug = true`。
- **JS 规则内部的 `java.ajax()` 走 `JsExtensions` 自建的 `AnalyzeUrl`，不置位** → 照常联网，不受本地调试影响。
- Web 端 WebSocket 调试（BookSourceDebugWebSocket 等）、源校验（CheckSource）、正常阅读/搜索均不触碰该标志，行为不变。
- 网址分支在发起任何请求之前就终止，`ConcurrentRateLimiter`、OkHttp、BackstageWebView、Cronet 路径自然全部绕过。

### 3.4 日志呈现

- 网址分支：`≡本地调试：规则算出请求 GET https://…`（含 headers/body 摘要）+ `≡本地调试：未取网页内容，调试结束`。
- 内容分支：`≡本地调试：规则返回内容，直接解析`；该内容照常经 `Debug.log(state=10/20/30/40)` 输出，**"源码"查看菜单（menu_search_src 等）功能不变**。

## 5. 边界与已知限制

- **判定启发式**：计算结果既非典型 URL 也非典型内容的极端写法可能误判；判定规则集中在纯函数中，后续可调。
- **纯 URL 源只能验证到"算出请求"**：解析规则没有内容输入是"不联网"的必然结果，不是缺陷；需要完整链路时关掉本地调试即可。
- **链路推进深度取决于规则**：只有各阶段规则自己取回内容（JS 内 `java.ajax`）时链路才继续深入，否则在下一个"网址"阶段结束。
- **动态 token/签名接口**：同一调试会话内规则多次执行会多次真实请求，行为与普通调试一致，无需额外处理。
- **留存复用（上一版方案的 CacheManager 留存）已废弃**：本地调试完全即时，不落盘、不依赖历史调试。

## 7. 验收方案

验证顺序：单测 → lint（本地最后门禁）；编译任务用 `:app:compileAppMaxDebugKotlin`（多变体歧义，勿用 compileDebugKotlin）。

手动验收（`installAppMaxDebug` 装包）：

1. **JS 源**（searchUrl 为 `<js>java.ajax(...)</js>` 返回 JSON）：开启本地调试 → 输入关键字 → 日志立即出现搜索解析并产出书单（期间仅规则内 `java.ajax` 联网）→ 详情阶段打印算出请求后结束。
2. **普通 URL 源**：开启本地调试 + 飞行模式 → 调试 → 各阶段仅打印算出请求、零联网、按提示正常结束。
3. **回归**：关闭本地调试，全链路照常联网运行，与现有行为一致；Web 端调试与源校验不受影响。
4. **RSS 源**：重复 1/3 关键路径（分类列表 → 正文）。
5. 内容分支下"源码"查看菜单仍能查到该阶段内容。

门禁同步：改动若命中 `docs/help-doc-sync/map.json` 受管代码路径，按 pre-commit 钩子提示同步对应帮助文档；debugHelp.md 与 updateLog.md 随实现一并更新。
